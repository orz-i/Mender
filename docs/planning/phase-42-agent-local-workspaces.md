# Phase 42 — Local Agent workspaces without Sandbox coupling

- Status: **implementation closed; complete automated and isolated CLI acceptance passed** (2026-10-17). Actual native Wails GUI click not confirmed because macOS Accessibility automation is unavailable.
- Authority: [ADR-0049](../architecture/adr/0049-agent-owned-local-workspace-paths.md).

## Intent contract

**User outcome:** Selecting a local project directory for an existing Agent is as easy as selecting its first `workspaceRoot` on Agent creation. Existing Sandbox resources are optional, irrelevant to Agent cwd selection, and remain independently governed when exposed as Workspace Tools. A user entering `GAR` sees the normalized alias `gar` and a directly choosable local directory. No duplicate Agent or tool creation.

**Hard boundaries:** Only owner-selected validated paths are persisted, runtime model arguments name only an approved alias, Profile workspace selection requires a separate explicit grant, and the admitted Task's key and root must be verified in the same SQL admission decision. Never use raw Tool cwd, Sandbox-derived implicit Profile grants, remote CLI fallback or compatibility bridges.

**Scope:** ADR/docs; SQLite v9 migration with owner/isolation/readiness-safe legacy mapping; Agent application and admission; HTTP/OpenAPI/SDK/Wails/CLI; one focused Workspaces dialog; regression and native smoke tests. Do not commit files under `.agents/`, `.pi/`, `.intent-loop/`, `.commandcode/`. Do not modify the user's live Agent, Profile, Sandbox or Tool inventory during regression tests.

## Commit boundaries

1. **A — Docs only:** ADR-0049, Phase 42 intent and acceptance (commit first).
2. **B — Domain / store / application:** explicit local root, migration v9, direct owner registration, per-Task exact target/authorization verification (commit after Go tests).
3. **C — Surfaces:** remove `sandboxId` from Agent workspace contract, update management API/CLI/OpenAPI/SDK/Wails, direct path selector and alias validation, refreshed i18n and UI tests (commit after parity).
4. **D — Acceptance/closure:** isolated real HTTP and MCP tests, v8→v9 snapshot/identity comparison, full `pnpm check`, Wails native rebuild smoke only when live tasks/leases zero, documentation (final commit). No real billable model request for this change.

**Potential risk:** legacy workspaces may refer to stale/unavailable Sandboxes; never silently resurrect their root or discard Profile grants. Fail migration with an actionable validation error instead of deleting or reassigning them. Historical Task snapshots are unaffected by binding migration.
## Verified implementation and acceptance (2026-10-17)

The user reproduced a disabled **Add workspace** confirmation with uppercase alias `GAR` and a ready local Sandbox already selected. The front-end silently rejected uppercase; more importantly, Agent workspaces were incorrectly required to point to a local Sandbox even though Mender's ACP Runner only needs an owner-approved canonical local directory. This phase hard-cuts the Agent-specific dependency while preserving Sandbox Workspace Tool routing as a separate capability.

- **A (documents):** `2fe4890` accepted ADR-0049 and this Phase 42 contract before code.
- **B (application/database):** `1fce5f9` moves Agent workspace storage to canonical absolute `workspaceRoot` (no SandboxID), upgrades Agent SQLite schema v8→v9, and removes the injected Sandbox Resolver. On registration the owner must select an existing local directory; after a task selects an alias, the Agent application rechecks its canonical root and SQLite atomically compares **AgentID, alias, exact approved root and Profile workspace grant** when admitting the Task. The host ACP launcher independently checks the root. Tests cover invalid/nonexistent roots, explicit grants and revocation, alias rebind races, symlink substitution, and migration failure/rollback when a legacy Sandbox is invalid. An existing legacy local Sandbox binding is converted once only when its backend, readiness, owner, isolation, canonical directory and integrity can all be verified. No dual-read or compatibility switch is introduced.
- **C (management/UI):** `f8e70a9` changes HTTP/OpenAPI/SDK/Wails/CLI `BindAgentWorkspace` to use `workspaceRoot`. The focused Agent Workspaces dialog accepts an absolute directory typed manually or chosen via the native directory picker, normalizes `GAR` to `gar`, and shows validation hints instead of an inexplicably disabled button. No Sandbox listing or resource creation is involved. `b363910` ensures backend errors are also visible **inside the focused dialog**, rather than only behind its modal overlay. The editor never implicitly assigns Profile grants.
