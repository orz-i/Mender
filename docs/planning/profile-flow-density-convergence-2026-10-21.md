# Profile 高频操作与信息密度收口（2026-10-21）

## 基线与实际问题

- Mender 是向 LLM / Agent 聚合、治理和供应工具与资源的平台。以普通用户的操作路径为中心，不能因简化 UI 改变 Profile 权限语义。
- 已审计当前 Wails 编辑页截图、`profile-edit-page.tsx` / `profile-tool-source-picker.tsx` / `profile-detail-page.tsx` 及此前 Profile 实机验收记录。
- 原有“列表 → 详情 → 独立编辑 → 来源 → 工具”的基础边界正确；不回滚此前拆分和操作菜单治理。
- 仍存在如下具体问题：
  1. 从已选来源的工具列表发起添加工具，打开的选择器又回到全部来源，需要再选一次刚刚查看的来源。
  2. 工具选择器的加载 / 搜索 / 保存错误呈现在选择器面板外，远离失败操作。
  3. 编辑器三层标题和重复操作说明占用首屏；在“直接”或“动态”固定模式下，重复暴露方式徽标和筛选器缺少区分价值。
  4. 选择器缺少跨来源的已选总数和明确的“有未保存修改”反馈，用户不易判断保存影响的范围。
  
## 本轮改动范围

### A. 更短的添加工具路径

- 在已选来源的管理子页点“添加工具”，直接打开该来源的工具选择列表；仍允许在选择器中返回全部来源并切换来源。
- 在来源列表或来源不可选时，仍打开全部来源选择器；历史未知来源保持只读管理，不尝试把失效来源添加至选择器。
- 新建 Profile 后仍进入独立编辑页；默认突出工具视图，让下一步更明确。概览 / Tunnel 继续可访问。

### B. 编辑页清晰与稀疏

- 用单行层级导航展示当前来源位置，省去分离的“返回来源”和工具页冗余教学文字。
- 来源列表只强调来源名、已选数量与异常可用状态；编辑单来源时保留搜索、必要筛选、操作菜单。
- 固定曝光模式不显示不可改变的曝光筛选和每行冗余标签；混合模式保持筛选与每行直接/动态标识。
- 工具治理、展示、凭据、确认移除等能力完整保留。

### C. 选择反馈与错误局部化

- 选择器的错误在其内容内以警示消息展示；错误时不把“无匹配结果”误当成最终检索结果。
- 选择器底部标注当前跨来源已选 ToolID 总数，存在修改时明示尚未保存；取消回滚草稿，保存保持原有业务接口与所有绑定字段。
- 不自动勾选新出现的工具，不新建授权模式，不改变 Mode/Tunnel/Policy/Credential 数据。

## 验证与边界

1. 测试：从来源进入添加工具直接打开当前来源；返回选择器来源列表后仍可跨来源；取消不提交；提交保留原 ToolBinding 高级字段；固定与混合模式差异；失败就近显示。
2. 检查 TypeScript、ESLint、i18n、Vitest、前端构建，避免测试退化。
3. 在真实 Wails 通过 HMR 或重建查看信息密度；需要写入 Profile 的操作只用隔离测试客户端，**不直接修改当前生产 Profile**。
4. 生产 Wails 与 Web 测试运行时分开记录，不能把模拟 API 截图冒充原生写入成功。
