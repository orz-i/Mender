## Cancellation handoff and preview starvation correction

- **Commit `32f183e`**: a request withdraws its in-process offer if cancellation or timeout wins **before** persistence starts. If persistence has started, the request waits for and acknowledges its final database result; it can no longer randomly drop that result because context cancellation and commit channels both became ready. Owner persist uses a bounded context and a separate acknowledgement deadline. Any existing Policy-version conflict continues to return an active request to manual review; duplicate owner/Policy selections remain reserved one at a time.
- Deterministic Race Detector tests cover both pre-commit withdrawal cases, Policy-conflict retry, cancellation and timeout becoming ready concurrently with a **completed** database result, and a real in-process owner/requester handshake cancelled mid-persist. Stress tests ran 10 repeated rounds without race findings.
- **Commit `bc1929c`**: the ACP outbound transport itself checks the Task context after the permission callback; its isolated new test ran 20 Race Detector rounds and rejected every cancelled, late one-shot response. This means `allowed_once` is still an authorization receipt, **not evidence of an externally delivered ACP response**. A process dying after SQLite commit can leave an allowed record without executing a tool; there is no protocol-level receipt/ack from the Agent for native ACP choices.
