# Mender 原生窗口 UI/UX 深化治理（2026-11-05）

## 实机证据
已在用户解锁的 Mac mini 上打开运行中的 `mender-desktop.dev.app`，窗口调整到约 1560×934，直接以 Wails 的真实数据观察下列页面，临时截图仅留在 `/tmp/mender-ux-actual-*`，不提交含真实记录的截图：
- 审计 `01-audit`：失败记录可见，但 Principal 主要是被截断的内部 ID，失败分类显示 `execution` 等技术词，过滤异常需多次操作。
- Agent 列表 `02-agents`：4 个资源只有 CLI 状态、名称和重复的工作区路径；看不到需要关注的历史结果。
- Agent 详情 `03-agent-detail`：实际已有 17 个 Task、1 个 Profile 授权，但概览只提供静态字段，查看任务/风险必须切换到其他分区。
- 工具来源 `04-tools`：已存在多个来源、管理动作；清单信息尚不便扫读。
- 配置档 `05-profiles`：仅 1 个 Profile 的情况下内容布局稀疏，不应人为灌入无意义卡片。
- 插件市场 `06-plugins`：按能力分类的外观已建立，但选择项目后仍需进入详情才能配置；存在额外操作步骤。
- 沙盒 `07-sandboxes`：8 个项目，已销毁的历史项与当前可用项混排，多个重复名称增加扫描成本。
- 概览 `08-overview`：工具、调用、Profile 已加载；失败记录可见，但没有直接串起“待处理 → 查看原因”路径。

实机截图尺寸、环境和业务状态可能受当前窗口与运行时数据影响；此评估不把 Wails UI screenshot 视为权限/后端状态正确的证明。

## 本阶段治理目标
**优先通过已有数据与既有 API 解决用户任务，而不是增添自造指标和图标。**

1. **Agent 详情主视图**：将任务的真实 queued/running/unknown/failed 状态汇总，展示最近任务、需审查的执行结果，并在同一视图直接查看 Task 结果；静态模型、路径和删除操作收至次级区域。严守 unknown 不代表失败/成功，绝不自动重试或接管 Agent Loop。
2. **审计可读性与纠错路径**：复用 Overview 已有 Profile 身份解析，让调用方从原始 Profile ID 显示为名称（原值仍可搜索、详情保留）；失败原因分类转成可理解文案；提供基于真实记录的 “需关注” 快筛。额外 Profile 元数据读取故障不阻断审计。
3. **沙盒列表信息层级**：默认只显示未销毁项，已销毁历史可在明确“历史”入口查看；保留 Ready/Unavailable 区分及所有状态访问，不删除数据。
4. **Runtime 数据单位**：显示层将精确可换算的 ms/bytes 转为 min、KiB/MiB，并在 tooltip 保留原始数值；编辑/校验与后台提交仍使用原有精确值。
5. **Plugin Marketplace 快捷创建**：对于已提供合法 `createAction.href` 的可创建项目，入口直接进入创建流程；在保留插件说明详情的同时减少一个强制页面跳转。不能为无可用创建动作的插件伪造入口。
6. **验收**：本机 Wails 导航/详情前后截图、Chromium 辅助交互、桌面和 390px 响应式、全量 TS/ESLint/i18n/Vitest/Web/Desktop 构建。真实破坏性操作只读审计，不在用户数据上做写入测试。

## 不变量与边界
Mender 保持工具/资源聚合、治理与供应定位；不修改 Agent Loop / ACP、后端协议、数据 Schema 或旧数据，不引入状态兼容桥。不隐藏权限、审批、错误、未知结果或历史信息。沿用当前本地 `main`，分段提交，不主动推送。
