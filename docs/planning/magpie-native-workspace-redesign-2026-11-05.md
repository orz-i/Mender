# Mender Magpie 级别的原生窗口 UI/UX 重构（2026-11-05）

## 参考输入
用户提供 Magpie 五张实机截图：Agents、Add a provider、Routing（含嵌套）、Usage，以及 https://github.com/yetone/magpie/tree/main/site/public/img 中同名截图。以截图所呈现的**内容组织和交互模型**作为验收标准，而非仅参考 CSS 色值。

## 上轮问题
现有 Mender 仍然是左侧 13 项菜单 + 二级标签 + 零散的卡片/数据表的传统管理后台。Wails 实机截图显示 Runtime 页面只在顶部显示四个指标，余下大面积空白。即使支持「顶部导航」切换，也出现两排导航，并没有形成 Magpie 的单一顶栏。前轮所有单测和浏览器模拟通过不等于真实视觉符合设计要求。

## 新 IA/结构决定

| Magpie 核心模式 | Mender 对应 | 约束 |
|---|---|---|
| Logo + 单行居中顶栏（8 个一级页）+ 工具/设置 | 8 个一级页：概览、工具来源、工具、配置档、智能体、沙盒、技能、审计；右侧搜索、审批、刷新、设置 | 不再保留左侧侧栏/布局切换/额外二级全局导航；桌面不需要理解 Workspace/Advanced 分类 |
| Agents 紧凑单平面列表 | Agent 列表：名称、可用性、运行后端/工作区、进入详情 | Mender 无 enable/disable Agent 的原生授权语义，不使用假开关 |
| Add Provider 多类别紧凑选择网格 | 插件发现：按能力种类分组的一页式目录，紧凑 tile，已安装/不可用真实状态、搜索/筛选与选择入口 | 不制造不存在的 vendor/模型/订阅选项 |
| Routing 解释模型与实时状态 | Mender 资源供应路径：Tool Source → Tool/Skill → Profile → 客户端/Agent | 展示真实既有实体的管理/关系，而不是造假的模型请求路由 |
| Usage 可观察的指标+图 | 调用审计：真实记录生成最近样本的状态/日分布条形图与完整事件列表 | 数据只有最近 100 条记录时，必须标为「最近记录样本」，不得宣称全量历史 |
| Magpie 单任务工作区 | Runtime: 概览+预算+隔离同页连贯呈现，不再在只读 Runtime 标签下留空 | 编辑预算、隔离权限仍在显式确认弹窗，危险权限提示必须保留 |
| 内容导航与设置分离 | 常用功能顶栏；Tunnels/Credentials/Policy/Runtime 等在齿轮菜单按工作目的可达；Approvals 有独立入口与未决数量 | 保留全部现有路由、键盘快捷键与中英本地化 |

## 视觉测量目标
- 背景 Magpie 浅色：`#f4f4f6`，面板白色、边框 `#e3e3e8`；页面默认浅色，可在齿轮切换浅/暗/系统（用户提供截图全部浅色）。保持品牌独立。
- 桌面单行顶栏约 56px；品牌左、导航居中、右侧轻量动作。导航 pill 选中为白底微阴影，未选中灰字；不再使用多排二级导航。
- 内容最大宽度 1600px，左右 22–30px 安全边距；主要工作区一页一意图；紧凑行高 64–86px，分隔细线。
- 小视口 390px：折叠菜单、当前页标题和可达的设置，不发生 body 横向溢出；对象详情既有局部导航独立运作。
- 首屏信息负载：不得只有统计条 + 一大片未说明的空白。无记录状态给出简短事实、配置入口或用户下一步动作。
