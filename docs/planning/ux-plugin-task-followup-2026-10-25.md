# Mender UI/UX 实机审计：插件返回上下文与 Agent Task 渐进披露（2026-10-25）

## 本轮真实证据

- 使用 Mac mini `/Users/mini/Coding/Mender`，确认原生 Wails DEV + Vite `127.0.0.1:9245` 的最新前端已生效；旧的孤立桌面二进制会显示过时 UI，因此不将旧版 `Principal` / `completed` 视为未修复问题。
- 通过原生 macOS 辅助功能点击实际页面与可访问元素，并用原生窗口 ID 截图。截图暂存 `/tmp/mender-audit-now/`，不提交仓库。
- 已完成只读路径：概览 → 插件市场 → AnySearch 详情 → 连接弹窗 → 取消 → 工具页；配置档列表 → 创建（不提交）→ 详情 → 来源工具；Agent 列表 → OpenCode 详情 → 任务 → 失败和状态未知任务结果（不提交任务、不恢复）。
- 概览调用方翻译、Profile 独立创建和来源优先工具列表、Agent 短工作区路径等既有改造已核对，不重复设计。

## 已确认问题

1. **P1 连接取消丢失来源上下文**：`PluginDetailPage` 的 `createAction.href` 指向 `/tools?create=1&offeringId=...`，工具页打开连接弹窗并移除查询参数；点击取消后停留在 `/tools`，原插件详情不再可见。应仅在来自插件详情的明确创建意图上恢复上下文；成功连接后仍保留工具服务清单，且所有后端操作只在提交时触发。
2. **P1 Agent 任务结果先出现诊断字段**：真实结果弹窗在最关键的错误/结果和“状态未知”告知之前，先列预算、截止时间、模型、心跳、会话和进程证据。需要用户先看到状态对应的结论和必要风险，再主动展开诊断数据。现有执行证据、原始 TaskID、生命周期和授权告知不能丢失。
3. **任务列表无法识别任务内容（记录为数据契约遗留）**：`AgentTask` 列表仅有 TaskID、状态、时间等字段，没有安全可信的用户任务标题。不得把结果、原始 Prompt 或 TaskID 尾号伪装成任务摘要，也不得因为旧的 `unknown` 记录自动恢复或重复提交任务。本轮不新增后端数据列、Agent Loop 管理或会话桥接。

## 修复范围与不变量

### A. 插件连接的发起位置

- 从真实插件详情跳转时传递受限制的本地返回上下文；工具页首次载入时保存，避免消费深链查询参数后丢失。
- 用户按「取消」、Esc、关闭按钮或弹窗外部关闭时，来自插件详情的操作应返回原插件详情；从工具页直接添加服务的普通弹窗关闭仍保留工具页。
- 成功连接仍停留工具页以查看服务；失败保留弹窗错误供用户更正，不能误报已连接。
- 保留插件安装、供应源、Profile 授权以及现有 API 的职责边界。

### B. Agent 任务结果信息层次

- 弹窗优先显示完整任务标识和真实状态、诊断结果（或已有结果文本）。`unknown` 必须第一层显式提示无法确认结果，禁止自动重试。
- 把预算、截止时间、模型、执行证据收纳到原生可键盘展开的「执行详情」区；原始数据不截断、不聚合推断，不移除观察与原生执行器心跳之间的区分。
- Host/ACP 审批覆盖范围说明、刷新与关闭仍可达；无结果/无执行证据有真实后备说明；不改 Task status、不更改 recoverability、不增加 Resume/Retry 按钮。

## 验收标准

1. Vitest 覆盖插件详情 → 连接 → 取消返回，以及工具页直接进入创建与成功连接的不同路径；Esc/对话框关闭行为保持一致。
2. Vitest 覆盖未知状态风险提示、失败诊断、已完成结果优先可见，技术区默认折叠并可展开，技术字段完整存在，刷新状态依然只调用既有查询。
3. ESLint、TypeScript、i18n 中文覆盖、Web/桌面构建、相关与全量 Vitest。最后用最新 Wails DEV 真实 UI 重测取消、任务结果和键盘/窄屏可见性。测试期间不创建、删除、取消、重复提交任何真实任务或工具服务。

## 尚未覆盖

- 真正授权的 Agent 委派执行、服务安装与创建的副作用路径，以及 390px 的独立移动设备表现；本轮不通过更改已有任务记录来“验证”恢复能力。
- 完整屏幕阅读器和 WCAG 2.2 AA 合规性。此项只验证所改弹窗的键盘/DOM/布局。
