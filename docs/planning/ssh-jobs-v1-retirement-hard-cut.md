# SSH Jobs v1 Retirement — hard cut to v2

- Date: 2026-10-14.
- **Intent:** remove v1 execution, protocol selection/activation UI and API, v1 read/inspect compatibility and v1 task payloads. SSH Backend remains the sole owner of task journals; Mender Core only admission/fencing/audit/lifecycle. No migration runtime bridge or global RemoteTask.
- **Initial real-host inventory:** Rocky `sbx_1b80d48ebb2591ecae6df534d9721e63` has 7 task directories in the physical `.mender-ssh-jobs-v1` root, of which 5 are v1 (4 terminal with exit artifacts, 1 manifest-only and UNKNOWN) and 2 are successfully completed v2. Systemd reports no active managed units, no Mender SSH runner processes. Core Run is Ready, schema 17, one-way v2 selection. Admission has been paused before making remote changes; no execution lease is held.
- **Why simple deletion is incorrect:** v2 completed journals share the old-named physical root. Removing the old TaskID directories without an immutable replay ledger permits a later client to reuse a previously accepted 128-bit key. The old v1 `unknown` record does not prove the shell command never ran, and a late v1 shell writer must not be able to create the deleted path and launch a unit.
- **Target:** new SSH Backend private root `.mender-ssh-jobs-v2/<SandboxID>/` holding ONLY validated v2 task directories. Do not rewrite existing v2 manifests, scripts, digests or results. New v2 scripts use the new root; completed old v2 copies are archival/observable and never relaunched. The shared task identity SHA-256 derivation remains stable across protocol hard cut — it is an idempotency identity, not a v1 runtime bridge.
- **Version-neutral replay prevention:** `.mender-ssh-jobs-v2/<SandboxID>/.retired-ids/<TaskID>` is an immutable private, durable marker for retired tasks, any protocol. All v2 submits check the marker **before** TaskID reservation and refuse it, regardless of command; no v1 parsing or replay is required at runtime. Retained marker has no command, stderr, stdout, old manifest, credential or host key. The migration must atomically write/fsync each marker before deleting the corresponding task. A missing/corrupt marker, partial copy, unknown task or symlink fails closed.
- **Old remote writer safety:** while Core admissions are paused and all old runtimes stopped, verify all exact managed services inactive and no task writers. Migrate/copy v2 data, create durable retired-ID tombstones, then replace the old physical root directory with a **private regular-file guard at the same path** and fsync its parent; an old v1 or v2 dispatcher attempting to create/access its old script path then fails before it can run. Guard is a host safety barrier, not v1 data or a runtime compatibility path; no code references it. Archive old raw material privately for offline incident audit prior to any irreversible deletion, with explicit expiry/manual handling. Do not try to classify the old v1 UNKNOWN as terminal.
- **Core/DB hard cut:** schema 18 explicitly drops version-activation tables and audit UI routes. New binaries accept schema 18 only (old binaries reject it during startup). No runtime reads of `sandbox_ssh_job_protocols`, no per-Sandbox protocol chooser, no v1 execution or capability fallback. Keep managed Job admission Pause/Resume and Core execution leases. No need to rewrite task outcomes in SQLite (they were never stored there).
- **Cutover sequence:** (1) documentation and tests, (2) code release + full checks, (3) transactional local SQLite backup, (4) remote v2 copy and markers with no overwrites; verify exact manifests+digests, (5) stop old Wails and tunnel, (6) atomically rename old physical root and create guard (abort and preserve quarantine on failure), (7) start only new v2 binary and apply schema18 migration, (8) verify v2 result/logs and new random v2 task from Profile, (9) resume Core admissions, (10) remove only verified obsolete task payloads after retained audit package, and finalize Git.
- **Acceptance:** complete removal of legacy v1 submit/read logic, selector, UI and OpenAPI routes; Go tests incl race and full `pnpm check`; no legacy source imports; v2 journal integrity preserved; original v1 idempotency keys cannot replay; old paths protected; v2 lifecycle remains fail-closed if evidence disappears; no blind `unknown → completed`; pre-existing local user Skill directories untouched.
- **Abort conditions:** remote preflight mismatch, evidence drift, live old writer/unit, unsupported fsync/flock, unable to preserve v2 immutable bytes, inability to establish guard/marker durability, active Core lease or old Runtime concurrently serving. If any abort occurs, keep Sandbox paused, leave remote data untouched/quarantined and report explicit blocker instead of destructive best-effort cleanup.
