## Stage E blockers that F must remove or explicitly retain

1. **Profiles:** one native operation merges multiple formerly Sandbox-pinned Tools. A new Profile ToolBinding must contain exactly the old authorized Workspace/Sandbox pairs, not all accessible Sandbox grants; disagreement in alias/policy/concurrency/credential/direct requires explicit conflict resolution.
2. **MCP presentation:** Agent as Tool may retain its ToolID while the source namespace changes. New direct exported names require an owner-reviewed per-Profile manifest, no silent redirects or duplicate names. The same applies to native Workspace and SSH Jobs.
3. **Policy:** typed SourceRef is the operation origin; Provider Activation remains distinct. Old Provider selectors with resource facades require semantic translation or must block.
4. **Workspaces:** local placement root ≠ remote content equivalence; Agent workspace root needs independent profile authority and ACP v1 Task/Session retention.
5. **SSH Jobs:** must retain native JobID→Sandbox ownership, remote evidence, observation, cancellation and no auto-replay of uncertain jobs.
6. **Schema and restart:** old binaries fail closed on the new version, typed runtime cannot reintroduce facade rows; backup restoration must be whole-DB and version-matched.

## Initial F1 acceptance boundary

Build a read-only adapter over the **new** Schema only. It must not call `bootstrap.NewRuntime`, register an Agent/backend, mutate Profile grants, or invoke a Tool. It may identify an Agent source only when its exact Profile grant exists; it may expose a native Tool only with one or more exact currently valid target scopes and corresponding Workspace placement. It must fetch only Tool metadata required for Profile-scoped supply, never secrets or raw Task/Job data. For Direct/Hybrid, export only exact selected ToolIDs, with collision rejection and independently reviewed source labels. Source names and ToolID stability do not authorize execution.

The F1 adapter is *not* the final Stage F release. Its tests use disposable Stage E candidate SQL with a real Bootstrap-created local Sandbox and an Agent as Tool; they cover grant/revoke, SourceRef accuracy, duplicate exports, Profile-restricted browsing and stale cursor handling.

## Implemented F1 — Profile-scoped typed source discovery

- `backend/internal/profile/infrastructure/typedsupply`: Future **read-only, query-only** adapter. Requires Catalog v3, Profile v8, MCP delivery v2 and the Stage E migration marker; refuses legacy Provider-backed schemas and missing stores. It lists only the exact Profile's ToolBindings and validates each typed Tool SourceRef before display. Real Providers require a configured Provider; Agents require their exact AgentGrant; Native Workspace/Jobs Tools require a host-reviewed ToolID plus exact TargetScope and Sandbox Grant. Workspace Tools additionally require an independent Workspace Profile grant and a persisted Workspace→Sandbox placement.
- Direct/Hybrid/Dynamic export is derived only from selected Profile ToolIDs, validated against each tool's actual SourceRef; new typed names are **not** automatically published by the legacy MCP server. Duplicate direct exports block. Source-scoped browse uses opaque v2 cursors including a full Profile-filtered snapshot fingerprint: revocation or presentation changes cause stale-cursor rejection rather than exposing a previously selected source.
- The Profile projection returns source groups, names and bounded metadata; it intentionally does not include credential references, raw Tool arguments, Agent transcripts or remote Job records. These results are **not invocation approval**. The caller must revalidate the scopes/grants and Policy on every actual Tool invocation.
- The Stage E future SQL candidate was tightened to require an explicit Workspace Profile grant as well as Profile ToolBinding, exact TargetScope and Sandbox capability grant before a new Native target scope can be inserted. Insert/revoke of Workspace, Sandbox, Agent grants and target scopes now increment Profile and MCP delivery revisions. This is future-schema hardening, **not a running v2 migration**.

## Implemented F2a — atomic Native Workspace lease reservation

- `backend/internal/sandbox/infrastructure/typedlease`: Tested **future-only** lease store. Requires a migrated database and trusted `InvocationAdmissionVerifier`; the verifier must confirm an Invocation already admitted by the canonical Policy/Approval pipeline. A matching ToolID, WorkspaceRef or Governance Facts alone cannot claim approval.
- A single SQLite `INSERT ... SELECT` atomically checks the exact pinned `native:workspace` ToolID + source key, Profile service identity, Profile ToolBinding (non-deny), TargetScope, independent Workspace grant, Sandbox capability grant, matching Workspace placement/root/isolation and Ready Run generation. It writes to the existing `sandbox_execution_leases` table — there is no second Task/lease manager. Reserve cannot silently substitute Sandbox B for A, and cleanup requires the matching caller/token.
- Tests prove all individual revocations fail closed, simultaneous Workspace-grant removal and reservation serialize safely, invalid ToolIDs/Approval facts are rejected, and the typed store refuses the old Schema. The test store does **not** launch a process, connect to remote hosts or execute a Tool.
- **F2b execution plumbing implemented (not production activated):** the canonical Invocation application adds a private, attempt-scoped proof to execution context **after** Policy/Approval and Runtime Budget/Binding admission. Tool approvals now identify the exact typed `SourceRef` rather than a mandatory ProviderID; real Provider Activation retains its own distinct action and `provider:<ProviderID>` source, while Sandbox/Agent lifecycle approvals do not forge a Tool source. Runtime Budget and serial execution group by actual source (preserving real Provider budget keys). `ApprovedAttemptVerifier` checks the exact InvocationID/ToolID/Caller/Governance Facts. Stage C `GuardedRouter.Acquire` binds that proof and FrozenPlacement to the existing `SandboxRouter.AcquireNative`, which **requires a concrete typedlease Store** and therefore rejects the old generic Provider-only lease store. The typed Store implements the existing `ExecutionLeaseStore` interface by atomically enforcing ToolBinding+TargetScope+Workspace Grant+Sandbox Grant+generation in the same persisted lease table; there is no second backend/session path or lease ledger.
- **F2b Policy-facts correctness:** both the legacy Workspace plugin and the native route now reuse `workspace/domain.NormalizeRelativePath` instead of retaining duplicated path normalization code. Stage C takes schema-validated original arguments, derives a normalized `workspace_path` in addition to `workspace_id` and `sandbox_id`, and freezes a defensive copy of execution arguments. Stage F2a rejects native reservations without an exact normalized `workspace_path` fact. Read/edit escape paths, spoofed Workspace IDs and changed approved targets are rejected before executing.
- **SourceRef Policy/Audit hard cut:** `tool.invoke` Policy validation now requires a canonical `provider:<ProviderID>`, `agent:<AgentID>`, `native:workspace` or `native:jobs` identity. The existing `providerIds` Policy selector only matches actual Provider Tools, never an Agent/Native Tool with a missing/fabricated ProviderID. Exact `toolIds`, known effects, and resource/path constraints remain in the single existing evaluator. `provider.activate` independently requires a real ProviderID; Sandbox/Agent lifecycle actions must not carry a Tool SourceRef. Invocation terminal Audit persists the actual ToolID without manufacturing an empty ProviderID for Native/Agent. No new Policy selector tables or approval engines were added.
- **Still required for Stage F completion:** connect one reviewed Native Tool Executor/fact extractor/target selector and Agent as Tool executor to the current canonical Invocation composition, including the final SourceRef-aware audit persistence and real result handling. A private proof can be consumed only **after** canonical admission: it is not a replacement for Policy, approval or an authoritative Profile scope. Do not enable native calls before this is complete.

## F2b execution-source closure (2026-11-07, future-only)

- Canonical Invocation `GovernanceFactExtractor` now receives the authenticated caller and returns **one** `GovernanceFactExtraction{Facts, Target}`. Only a Native Tool with an exact frozen target and matching known Policy facts can pass preflight. Invocation transports that same target through Policy/Approval/Budget into the existing execution request; it is **not a second authorization token**. Provider/Agent Tools have no sandbox target. The running Provider-v2 bootstrap rejects uncomposed Native/Agent Tool sources rather than silently guessing facts.
- The native `workspace` source implements its preflight using the existing `WorkspaceSelection` and `GuardedRouter.Resolve`, then consumes the same `FrozenPlacement` with the existing `GuardedRouter.Acquire` and typed `executeTyped` operation path. It never selects a different Sandbox after Policy. A routing-only `workspaceId` is removed before the legacy typed decoder, while size/operation normalization retain the original canonical request bytes. The existing Sandbox atomic typed lease and cleanup remain authoritative; no new placement/lease aggregate was introduced.
- The Agent-owned source reuses **the existing** `delegationprovider.Instance.Execute`/`agentapplication.Service` for `delegate/status/result/cancel/resume` rather than forking Task/Session/ACP logic. A strictly pinned AgentID is rechecked in both facts and execution; two Agent instances cannot borrow each other's tools. A shared host-reviewed fact helper avoids a duplicate Agent Policy definition.
- The **same** SourceRef execution Router can return facts from only its trusted native/Agent registered executor. It refuses facts provided by external Provider executors; external Provider facts continue through the existing host-reviewed Provider configuration extractor. Future F4 will assemble one source-aware fact/router composition and remove Provider-facade registration in the same release, not install a second live Invocation path.
- **Boundaries deliberately not claimed:** this adapter has no production registration, has not run a real native Tool through migrated Wails/MCP, does not implement `native:jobs` execution or full Agent Workspace migration, and does not retire the legacy v2 Facade. `native:jobs` remains fail-closed without a future target/verifier. F3 SourceRef MCP/HTTP/CLI/SDK/Wails and F4 coordinated source schema/bootstrap switch are still outstanding. Do not deploy this intermediate state with a migrated database.
