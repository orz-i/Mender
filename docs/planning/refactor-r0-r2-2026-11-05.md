## Contracts frozen

ProviderID, ToolID, SourceKey, config revision/version, installation pin,
Profile membership/grants, invocation outcomes and audit/activation sequence
remain authoritative. No schema changes or production dependency changes.
HTTP JSON fields, CLI machine output and Wails exposed methods/types retain
their existing meaning. Descriptor verification is an additive explicit owner
command; directory reads no longer attempt backfill.

The existing external resolver is offline/snapshot-based. Removing the old
backfill call path is a query-purity correction; it is not evidence that the
current resolver actually launched a process during a directory request.

## Dependency map

```text
HTTP / Wails -> management/application/query -> consumer ports
management/infrastructure -> query ports + existing application boundaries
bootstrap -> providerplugin/application -> providerplugin neutral types
provider infrastructure -> Catalog/Agent/Sandbox application boundaries
bootstrap -> agent/application admission -> Policy + admission audit ports
HTTP / CLI / Wails -> Sandbox application specs -> infrastructure mapping
```

Cross-table retirement/grant guards remain distinct from read-only management
projection. Neither is a general permission for application code to access a
foreign repository. Keep exact reference/race fixtures and one SQLite commit.

## Security review

- Directory reads have no verification, secret-resolution, instance-close or
  process-launch authority.
- Shared management views must retain sanitization and not project raw secret
  material. Source attribution is display metadata, never a grant.
- Provider activation still precedes external plugin validation/open, upstream
  discovery and route acquisition. Compensation retains stable identities.
- Agent require-approval remains rejected in this extraction. ACP native
  permissions and Mender Tool authorization are unchanged.
- Sandbox specifications do not let model arguments select weaker isolation.

## Implementation result

R0-R2 is implemented. No R3-R7 implementation was started. The verification
record below was captured before the subsequent segmented commits. No
deployment, production migration or resource mutation was performed. The
[Windows check follow-up](check-portability-2026-11-05.md) records the later
portability fixes, OAuth environment comparison and complete passing gate.

- R0: ADR-0059, the dependency map, exact deferred import exceptions and an
  AST-based architecture gate are wired into `pnpm check` and CI. The ADR index
  now reflects ADR-0057's partial implementation rather than proposed-only.
- R1: HTTP/Wails share management Provider queries and safe projection. Exact
  source attribution uses a read-only SQLite adapter. Catalog owns the pure
  source-discoverability predicate used by MCP and management; inert Sandbox
  capability/lifecycle observations still cross a bootstrap adapter.
- R1: directory queries no longer attempt descriptor backfill. The additive
  `mender plugin verify <installation>` command repairs a missing Provider
  descriptor explicitly. It owns a private verification process host, closes
  before publishing, and uses immutable fill-only CAS without a schema change.
- R2: Provider registration/update/sync/rebind/delete/activation and compensation
  live in `providerplugin/application`; Catalog snapshots and Agent/Sandbox
  ownership have explicit application boundaries. Atomic retirement remains in
  infrastructure behind a consuming port.
- R2: Agent admission moved to its application boundary. Sandbox creation
  specifications no longer expose concrete backend/SQLite types to callers.

### Complete-gate limitations

The following records the original R0-R2 run. The subsequent authorized check
portability fixes and new full-gate result are tracked in the
[Windows check follow-up](check-portability-2026-11-05.md); R3 is still deferred.

- `pnpm check` passed the new architecture gate, then stopped at the existing
  POSIX `GOWORK=off` assignment in the protobuf script under Windows cmd. The
  unrelated script portability change is outside R0-R2.
- The final full `go test ./backend/...` recorded 90 passing packages and 7
  failing packages. Six failing packages overlap the pre-change baseline above.
  The broad run additionally hit timing failures in
  `TestMissingReadPreviewDoesNotBlockLaterValidApproval`,
  `TestGovernedCanonicalAgentDelegationToolFixture`, and
  `TestAgentDelegationThroughMCPClientSession`. The full Agent application package
  and both Bootstrap tests passed when rerun in isolation. The fairness test
  uses the unchanged fake admission, not the extracted production Admit. These
  retries do not turn the failed broad run into a passing gate or establish a
  definitive cause of timing instability.
- Full backend lint reported gofmt issues in untouched working-tree files.
  Sample checks of Governance approval, Management server and Sandbox admission
  confirmed that converting CRLF to LF alone matches gofmt. No unrelated source
  files were reformatted to hide this checkout/environment limitation.
- Native Wails UI and real ACP/restricted-host/Docker/Daytona/external SSH smoke
  were not performed. Example Provider subprocess verification was exercised
  only with temporary test-owned files/processes.

Changed-file lint used an explicit patch containing both tracked modifications
and all untracked new Go files, with `--whole-files` so existing lines in each
touched file were checked too. It passed with zero issues after removing an
unused extracted helper and formatting the touched external-Sandbox fixture.
This affected-scope pass does not replace or conceal the failed complete gate.
