# Mender UI/UX 简化与能力保全 — 2026-10-19

## 意图与基线

本轮以普通用户完成工作为入口，降低认知负担与页面信息密度，同时 **保留全部现有能力、授权和治理边界**。仓库现有的 13 个 Web 路由与部分窄屏页面经浏览器初步审计；当前 :5174 Web 开发实例 /api/v1 返回 404，因此未把「0 条记录」当成真实业务数据，也不把空状态截图当成真实列表体验验收。

目标：用户能快速完成「添加工具 → 发现工具 → 供应给客户端」与「找到 Agent → 查看任务/审批」；页面以预览/列表为常态，编辑与高级设置按需进入；一个视口突出一个主要任务。

## 不变量

1. 保留现有路由、能力、数据结构和权限，不创建聚合后端或多套状态，不改变提供方/工具/Agent/沙盒的实际边界。
2. 导航按用户任务分层，但二级项目必须仍可达；不要只靠悬停和图标解释功能，移动端必须有文本菜单。
3. 显示数据加载、加载失败、确实为空应互斥；不能把 API 错误伪装成“没有对象/0 条记录”。
4. 每屏只突出一个主要操作。辅助项合并在工具栏；详情和编辑独立呈现，避免在小空间内塞统计、筛选、操作。
5. 无需新增“模式”或额外业务配置；快捷入口只导航到真实现有流程。
6. 遵守 React/TypeScript strict 与项目现有组件/i18n，键盘与读屏可用，考虑 390px 窄屏。

## 本轮交付切片（阶段 A，含关键入口）

A1. Shell 与导航：常用任务放在一级，客户端连接及治理功能可展开/可直达；标题、搜索、状态、通知优先级明确；移动端为有文字的菜单/抽屉，不再依赖 68px 图标栏。所有原路由可达，Cmd/Ctrl+K 保留。

A2. 概览：改为用户“状态 → 下一步行动 → 最近活动”的结构；初次使用只给一个最适合的下一步；数据异常显示失败与重试，不再展示虚假 0 和空历史，避免多项指标抢首屏。

A3. 关键入口错误态：插件市场和工具目录遇到 API 错误时，不再同时给“无插件/无服务”提示；刷新/重试入口可恢复。其余路由记录为后续覆盖。

## 后续迭代（不抢跑、不扩大当前业务结构）

B. 核心路径：添加插件/工具来源 → 查看工具 → 配置档 → 服务器/隧道，重点减少跳转、暴露明确下一步。
C. 全页面：卡片/列表/筛选/表单密度统一；Agent、Sandbox、凭据、策略高频动作直达、低频字段收进详情。
D. 接通真实 API，至少验证每条完整路径的非空数据、空数据、失败与重试；补充响应式、键盘、焦点、错误恢复回归。

## 验收标准

- 1440×900 和 390×844：无横向溢出；主要导航不遮挡正文；移动端导航能开/关并显示文字。
- 现有 13 个路由均能从菜单或明确入口访问；快捷搜索仍能导航。
- 概览与插件/工具关键页：error/loading/empty/data 四态区分。
- 不增加用户必选参数、持久化 UX 偏好或新业务抽象。
- 相关 TypeScript typecheck、测试和 UI 浏览器烟测通过；代码与文档分段提交，勿把未构建运行的页面当作实机成功。
