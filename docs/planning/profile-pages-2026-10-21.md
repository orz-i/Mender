# Profile 独立页面与单主题编辑（2026-10-21）

## 决策

Profile 原实现在 `profiles-page.tsx` 内同时承担列表、新增、管理、工具来源选择及单个工具治理（超过 1,500 行），管理弹窗叠加单个 ToolBinding 弹窗，内容密度过大、页面定位与深链能力有限。本轮将页面职能分离，不改变 Profile 聚合领域边界。

| 路由 | 职责 | 可写操作 |
| --- | --- | --- |
| `/profiles` | 列表、检索、分页、打开详情、创建入口 | 无 |
| `/profiles/new` | 独立新增表单；先定义标识与模式 | `POST /profiles` |
| `/profiles/:slug` | 只读详情：概览 / 工具；工具按来源钻取 | 无 |
| `/profiles/:slug/edit` | 独立编辑页：概览 / 工具；工具来源视图替代大弹窗 | Tunnel、ToolBinding |
 
Mender 的侧边栏仍只保留 Profile 一个导航入口；子页面以返回按钮和 URL 层级组织，无额外侧边栏项目。

## 信息层级

1. **列表**只展示显示名称与 Slug、模式、工具数量、Tunnel 与查看详情。详情打开独立页面。
2. **详情页**默认显示 Profile 属性；切至工具后先列来源，选择来源后仅呈现其工具及暴露／治理摘要。不存在保存控件。
3. **新增页**仅保留创建所必需的 Slug、显示名称、暴露模式；采用规范化预览、即时校验、原地错误；成功后进入新 Profile 编辑页选择工具。
4. **编辑页**默认概览；标识、显示名称、模式展示为只读元数据，Tunnel 才是可变设置。工具视图先列来源，再逐项管理工具。选择工具来源转为编辑页内单主题视图，避免与管理大弹窗套叠。单个工具的展示、策略、凭据继续使用有边界的小型对话框，保存失败在当前对话框内提示。

## 不变量

- 现有服务端仅允许创建 Profile、更新 Tunnel 绑定、增加／替换／移除工具。Slug、显示名称、暴露模式在当前服务端聚合中不可更新；**不假装在编辑页可修改，也不新建更新 API**。
- 工具选择严格按来源展示但按 **确切 ToolID** 授权；来源自身和未来新增工具不会自动获授权，跨来源选择保留。
- 更新工具成员资格时保留其他既有工具以及展示覆盖、别名、策略、并发约束、凭据引用。无法检索的历史 ToolID 保留在管理专用的「未知来源」分类，不能静默遗失。
- 保留别名验证、混合／直接／动态模式投影和原后端约束；Tunnel 设置与取消仍使用原 API。
- 关闭工具选择视图或工具级对话框不保存；请求取消及过期搜索响应不能覆盖新视图。错误就近显示。
- 不新增历史兼容桥接、额外持久状态或业务协议。路由组件对 Web 和 Wails 共享。

## 验收证据

- `pnpm --filter @mender/app typecheck`、`pnpm i18n:check`
- Profile 创建校验、路由跳转、来源优先选择、分页、远页 ToolID 回填、历史 ToolID 保留、覆盖字段保持、工具策略／凭据保存失败就近显示等 Vitest。
- 管理页集成回归（Profile/Tunnel/ToolBinding）与初始数据加载错误重试。
- Chromium + Playwright 浏览器冒烟：列表 → 详情 → 工具来源 → 编辑 → 选择工具并保存 → 详情 → 列表 → 新增 → 编辑。API 请求采用浏览器层模拟，避免写入用户真实 Profile 数据；浏览器渲染验证不替代 Wails 实机的构建重启验收。
