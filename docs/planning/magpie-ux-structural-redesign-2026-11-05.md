# Mender 与 Magpie 对齐：布局与任务路径治理（2026-11-05）
  
## 设计定位
不是“把 Mender 换上 Magpie 的皮肤”，而是借鉴 [Magpie GUI Shell](https://github.com/yetone/magpie/blob/main/docs/subsystems/gui-shell.md) 的**可发现导航、页面与二级导航职责分离、精确上下文、列表优先、响应式布局、低信息噪音**。Mender 继续是面向 LLM / Agent 的工具和资源聚合、治理与供应平台，不接管 Agent Loop；所有路由、供应边界、审批、审计、安全提示保留。

## 基线问题和验收假设
1. 一级导航默认只展开 Workspace，其余 Connections/Advanced 需要点击小分组，导致大部分能力首次不可见；改为可见的分组与所有一级入口，不要求用户猜测分类。
2. 列表进入详情后，顶栏仍是列表名；详情页还重复“返回列表”与对象标题；改为全局可点击位置路径（面包屑），对象详情有清晰的当前上下文，保留返回能力。
3. Agent 详情将七个语义不同的任务/授权/工作区标签挤在一行；改为宽屏独立子导航窄轨、手机可横向滚动的子导航，主内容保持连续且不被标签挤窄。
4. Profile 查看、编辑中的多层操作位置不一致；沿用同一“列表 → 对象 → 分区 → 编辑/供应”的可预期导航，减少重复的 Back 和局部标题。
5. Magpie 提供可选择的侧栏/顶部导航布局；Mender 增加同源入口的可保存布局切换，顶部模式不是重复铺满十余个图标，而是“分组选择 → 组内目的地”。
6. 布局不应降低可达性：移动端抽屉可访问全部入口，⌘K、审批提示、语言、状态保持；错误和未知状态必须保留明确文本。

## 导航信息架构
- **Workspace（工作区）**：Overview → Plugin Marketplace → Tools → Profiles → Agents → Sandboxes → Skills；按照“发现来源 → 选择工具 → 向客户端供应 → 使用智能体 → 运行环境/技能”的使用路径排序。
- **Connections（连接与供应）**：Tunnels → Credentials；跨端/跨服务连接前置能力。
- **Advanced（高级管理）**：Approvals（仅宿主端能力允许时） → Audit → Policy → Runtime；保留真实治理能力，所有分组始终可见，无隐式折叠。
- Sidebar 为桌面默认；Top 为偏好布局且记录到本机 localStorage。窄屏始终使用菜单抽屉。
- Header 包含可点击位置路径、全局搜索、审批入口、语言、运行状态和布局切换；不重复在详情内放置“返回列表”作为大按钮。
- 保留 Ctrl/Cmd+K 全局搜索；增加导航分组和对象上下文语义。

## 分区模式
- 普通列表：左边是过滤/视图选择，右边是搜索/刷新/创建；对象的可点击名称与行末动作清晰区分。
- 多分区详情（Agent、Profile）：主要工作区的内容和内部主题导航在不同层级，宽屏采用固定宽度的分区侧轨，窄屏退化为横向可滚动标签。重要操作保留在对应分区，并可见其状态与后果。
- 创建流程：单任务一页，取消/返回与继续/确认维持一组；Profile 创建后进入工具选择，不引入多余的假 Wizard。
- 危险操作继续使用确认对话框；未知状态不能显示为成功/失败。

## 回归验证
- 路由：13 个一级入口、详情、创建、编辑、交付路径保持完整。
- 交互：顶栏/侧栏布局切换持久化、⌘K、面包屑返回、抽屉、详情子导航、列表动作、审批。
- 视口：桌面 1280×800、窄屏 390×844；不允许 body 横向溢出。
- TypeScript、ESLint、Vitest、i18n、Web 与 Wails 前端构建；浏览器截图和真实 API 阻断边界分别记录。
- 文档先行、分段 commit；生产数据不改，暂不推送远端。
