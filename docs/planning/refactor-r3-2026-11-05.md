## Scope and ownership

| Area | Responsibility migration | Acceptance |
| --- | --- | --- |
| Agent resource use cases | Owner resource/default/workspace/grant management gets its own consuming storage port | Existing facade methods and identity/admission ordering remain |
| Agent Task/Session use cases | Submit/resume/evidence/cancel lifecycle gets a Task port and a narrow native-permission dependency | No duplicated active state or new execution entry |
| Native approvals | Permission request, policy mode, revision fencing and owner handoff get a dedicated storage port | Approval expiry, grant revocation and cancellation/release races retain results |
| Agent runtime | Active tasks, pending handoff, locks, cancellation and WaitGroup belong to one shared coordinator | Task and approval components use the same lifecycle object |
| Local workspace | Filesystem resolution/type observation moves to an explicitly injected infrastructure verifier | Application retains approved-root equality, lexical containment and error mapping |
| Invocation | One Execute coordinates private preflight, admission, execution and finalization collaborators | Single budget snapshot, stable ID, authorization/lease/result/audit/event order preserved |
| Architecture gate | Remove the three exact legacy imports and detect filesystem-bearing filepath operations | Zero exceptions; aliases do not conceal filesystem operations |

The SQLite Store remains one implementation of the smaller Agent ports. This
does not split databases, duplicate authoritative state or create new bounded
contexts. The Agent constructor now requires the filesystem verifier explicitly;
the composition root and internal test callers provide the local adapter.

## Preserved contracts and failure behavior

- Resource admission, ACP native permissions and Mender Tool Invocation are
  distinct authorization mechanisms.
- Keep existing owner/Profile checks, canonical approved roots, alias grants,
  native approval modes and Policy revision commit fences. Default/alias root
  recheck points and approval-policy path observations are retained, rather than
  silently strengthened as part of extraction.
- The verifier observes symlinks, directories and regular files. It does not
  authorize targets, provide sandbox isolation or eliminate filesystem TOCTOU.
- Invocation scope precedes Tool lookup; schema/facts precede policy and binding
  tightening. Approval precedes the execution deadline and lease acquisition.
- Runtime lease precedes binding lease; executor return releases binding then
  runtime leases before result guard and durable audit. Finalization retains
  audit context choices, joined errors and observer best-effort behavior.
- Audit failure must not produce successful output or a successful terminal
  event. Reviewed facts and credential capabilities retain their exact scope.
- Preserve timeout, cancellation, expiry, resume/recovery and unknown outcomes.
  No automatic retry or speculative recovery is introduced.

HTTP/CLI/Wails/MCP shapes, schema versions, Tool/Provider/Task identities,
configuration revisions and plugin protocols remain unchanged. R4 typed
Workspace execution, R5 Profile delivery/schema and R6 frontend capabilities
remain deferred. No production database or real backend/account is used to
validate this work.

## Implementation result

- `agent/application/Service` is a facade over ResourceService, TaskService and
  ApprovalService. Each component consumes its own storage interface;
  Repository remains an aggregate constructor dependency implemented by the
  existing SQLite Store. Atomic admission/resume/approval writes remain intact.
- `runtimeCoordinator` is constructed once and shared by Task and Approval.
  Cancellation, closed/admission locking, pending reservation and WaitGroup
  accounting retain their existing critical sections. Task consumes only a
  two-operation native-approval port rather than approval-policy storage.
- `LocalWorkspaceVerifier` is required by NewService. The infrastructure
  implementation imports only standard library packages. All seven symlink
  resolution and three type-observation sites moved behind it, including
  approval-policy automatic decisions. `localWorkspaceRules` retains the
  authorization-sensitive path comparisons and original error categories.
- Invocation's public entry coordinates preflight, admission, execution and
  finalization through one attempt. The terminal audit writer receives only
  bounded identity/classification metadata; it retains requested ToolID for
  unresolved attempts and resolved ToolID after lookup, as before.
- The architecture exception file is empty. AST checks now reject
  filesystem-bearing filepath operations, including import aliases and raw
  import strings, while allowing lexical helpers and shadowed consumer ports.
  This checks explicit source edges/mechanisms, not arbitrary runtime purity.
